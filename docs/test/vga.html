Guide / Getting on screen

VGA text mode

There is no print function and no graphics driver. You put characters on screen by writing numbers into a specific range of memory, and the hardware turns them into pixels for you.

A screen that is just memory

The video hardware is constantly reading a block of memory starting at address 0xB8000 and drawing whatever it finds there. You do not ask it to draw. You change the memory, and the next time it refreshes, the screen has changed.

That block is 80 columns by 25 rows, which is 2000 character cells. Each cell takes two bytes, so the whole screen is 4000 bytes. Writing to cell zero changes the top left character.

This is memory mapped hardware. The address is not RAM you own, it is a window onto a device. Reading it gives you what is on screen, writing it changes the display. No function call involved.

Why 0xB8000 specifically It is a legacy address fixed by the original IBM PC design and honoured by every PC since. The first megabyte of memory is full of these reserved windows, which is exactly why the linker script loads the kernel above it at 1 MB.

Two bytes per character

One byte holds the character, the other holds its colour. The lessons combine them into a single 16 bit value, which is why VGA_MEMORY is a uint16_t* rather than a byte pointer.

The character goes in the low byte and the colour in the high byte. Building that value is a shift and an OR, the same packing pattern as everywhere else in the lessons.

The colour byte holds two colours

One byte, two four bit halves. The low nibble is the foreground colour and the high nibble is the background. Four bits give sixteen choices each.

The lessons only define black and white, because the OS never needed more. But the full sixteen colour palette is there in hardware and available by passing different numbers.

From a row and column to an index

The screen is two dimensional but memory is a flat line. Converting between them is one multiply and one add, and this formula appears in every function in the driver.

Multiply the row by the width to skip whole rows, then add the column to move along the current row. Getting the width wrong here is a classic bug: text appears diagonally, because each row starts slightly offset from where it should.

Scrolling by moving memory

When text reaches the bottom row there is nowhere left to write. Scrolling means shifting every row up by one and clearing the bottom row, and since the screen is just memory, that is a single copy.

The copy length is worth reading carefully. It moves VGA_HEIGHT - 1 rows, not all 25, because the top row is being discarded and there is no row below the last one to pull from. Copy one row too many and you read past the end of the video buffer.

The scroll, from vga.cpp
memcpy(VGA_MEMORY, VGA_MEMORY + VGA_WIDTH, (VGA_HEIGHT - 1) * VGA_WIDTH * sizeof(uint16_t));
Destination is row 0, source is row 1, length is 24 rows worth of 16 bit cells. Note that adding VGA_WIDTH to a uint16_t pointer advances by 80 cells, not 80 bytes, because pointer arithmetic scales by the pointed to type.
Pointer arithmetic scales VGA_MEMORY + VGA_WIDTH moves forward 80 cells, which is 160 bytes, because the pointer is uint16_t*. If it were a uint8_t* the same expression would move only 80 bytes and land in the middle of row zero. The sizeof(uint16_t) in the length is there because memcpy counts raw bytes and does not scale anything.

Handling the special characters

Most characters just get written to the current cell. Three do not, and each needs its own branch in putchar.

CharacterWhat happens instead
'\n'column back to zero, row advances, scroll if that ran off the bottom
'\b'step back one cell, possibly to the end of the previous row, then write a space over it
anything elsewrite the cell, advance the column, wrap to the next row at column 80

Backspace is the fiddly one, because erasing is not the same as moving. The cursor has to go back, then a space is written to actually clear the character, and the cursor stays there so the next keystroke overwrites it. The lessons handle the case where backspace happens at column zero by stepping up to the end of the previous row.

Printing a number

There is no printf, so turning an integer into digits is hand written. The algorithm produces digits in the wrong order, which is the interesting part.

Taking the remainder mod 10 always gives you the last digit. So the digits come out backwards and have to be buffered, then printed in reverse. Adding '0' converts a digit value into its character, because the ASCII codes for the digits are consecutive.
