Guide / Managing memory

Paging

A translation layer between the addresses your code uses and the physical memory they land on. It is the hardest thing in the lessons, and the failure mode is a silent reboot with no message at all.

Two kinds of address

Up to this lesson there was only one kind. When the VGA driver wrote to 0xB8000, that was a physical location on the memory bus. Paging inserts a step in between.

Every memory access your code makes now goes through a lookup. The CPU takes the virtual address, consults tables you built, and produces a physical address. Your code never sees the physical one.

Why bother Three reasons. Two programs can both use address 0x400000 and get different physical memory, so they cannot interfere. An address with no mapping faults instead of silently corrupting something. And memory can appear contiguous to a program while being scattered physically. The lessons only need the second one right now, but the first is what makes user programs possible later.

How one address gets translated

A 32 bit virtual address is not treated as a single number. The CPU splits it into three fields and uses each one for a different step.

Ten bits index a table of 1024 entries, which is why the split is 10, 10 and 12. The bottom twelve bits are the offset inside a 4096 byte page, and 4096 is exactly what twelve bits can address.

Two levels of table

The lookup goes through two tables, not one. That seems like extra work, and it is, but it saves an enormous amount of memory.

A single level table would need one entry per page across the whole 4 GB space, which is 1048576 entries at 4 bytes each, so 4 MB of tables for every address space whether or not the memory is used. Two levels means you only create the second level tables you actually need.

The lessons create exactly one page table, covering the first 4 MB, and leave the other 1023 directory entries empty. That costs 8 KB instead of 4 MB.

What an entry looks like

Each entry is 32 bits holding both an address and a set of flags, which sounds impossible until you remember the alignment trick from the flags page.

Because every page is 4096 byte aligned, the low twelve bits of a page address are always zero. They carry no information, so the designers reused them for flags. The address occupies the top twenty bits and the flags fit underneath with no conflict.

The lessons use 0x3, which is present plus writable. That is the minimum for a page the kernel can read and write.

Identity mapping, and why it is not optional

Here is the part that causes the silent reboots. The instant paging turns on, every address is translated, including the address of the instruction the CPU is about to execute next.

Identity mapping means virtual address X maps to physical address X. Translation happens but changes nothing. That gives you a safe starting point: the kernel keeps running at the addresses it was linked for, and paging is active and ready to do something more interesting later.

The loop is doing something worth reading slowly. Entry i is set to point at physical frame i, so entry 0 covers bytes 0 to 4095, entry 1 covers 4096 to 8191, and so on. 1024 entries at 4 KB each is exactly 4 MB.

The triple fault

If the mapping is wrong when paging switches on, the machine resets. Understanding the chain is useful because the same escalation causes other mysterious reboots.

Why debugging this is so unpleasant There is no error message, no register dump and nothing on screen. The machine simply restarts, and it restarts before any print statement you added could run. The lessons verified this by running QEMU with CPU reset logging and counting resets, because that was the only way to see anything at all.

Turning it on

Two control registers, and both must be written in assembly because C++ has no way to name them.

The order is fixed. cr3 must hold a valid directory before the enable bit is set, because the instruction immediately after the write to cr0 will already be translated.

Where the tables themselves live

The page directory and page table have to live somewhere in physical memory, and they have to be 4 KB aligned because the entry format only stores the top twenty bits of their address.

This is why paging depends on the PMM existing first. alloc_frame returns a 4 KB aligned physical address by construction, since frames are aligned by definition. Using malloc would give an address with arbitrary low bits, which the entry format cannot represent.

What happens on an unmapped access

The 1023 empty directory entries are not a gap, they are a trap. Touching an address they cover raises a page fault, which is exception 14 and already handled by the interrupt table.

So the lessons get memory protection for free. Any access above 4 MB reports itself by name instead of silently reading garbage, which is a genuine improvement over the situation before paging.

What paging unlocks later

The lessons stop at identity mapping, which is the minimum that works. Everything paging is actually famous for builds on this foundation.

CapabilityWhat it needs
a heap larger than the identity mapped regionmap new frames into the address space on demand, instead of a fixed static buffer
user programs that cannot touch the kernelthe user bit in each entry, plus a separate directory per process
two programs both using the same addressswap cr3 on a context switch so each sees its own mappings
read only code pagesclear the writable bit, so a stray write faults rather than corrupting instructions

None of that is possible without paging on, which is why a lesson with no visible output is one of the most important in the project.
